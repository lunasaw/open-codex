# 模型与服务商切换

聊天输入栏的模型菜单中可以选择已配置的模型服务商，也可以在“模型与权限”中同时选择
服务商并填写模型 ID。新聊天会在创建时携带选择；已有聊天保留线程 ID、历史、权限、
计划模式及 Conda 环境，无需重启服务或新建聊天，下一条请求使用新服务商。

第三方服务商先在“配置 → 服务商配置”中设置 ID、名称、API 地址、认证及协议。
当前原生配置使用 `responses` 协议；仅提供 Chat Completions 或其他协议的服务需要兼容网关，
本功能不做协议转换。密钥沿用运行时配置和环境变量，不保存在浏览器偏好中。
模型目录由运行时提供，不保证列出每个第三方服务商的模型，可在“模型与权限”手动填写模型 ID。

## 生效边界

- 空闲聊天切换服务商立即重新绑定，下一条请求使用新地址。
- 正在运行的回复不能跨服务商热切换，需要等待结束或先停止；不会自动中断当前回复。
- 同服务商的模型和推理强度仍沿用原有线程设置和当前回复设置入口。
- “默认服务商”使用该会话工作目录的有效配置，不更改全局默认值或其他聊天。
- 未知服务商被明确拒绝时恢复原设置；超时或连接断开时保留待恢复状态，不假定切换成功。

## 实现

原生 `thread/settings/update` 和 `turn/settings/update` 没有 `modelProvider` 字段。
Host 在会话准入锁下核对线程状态，执行 `thread/unsubscribe`，随后通过 `thread/resume`
传入服务商和模型，并恢复会话设置。空聊天先通过原生命名接口持久化，不伪造用户消息。
页面只在 Host 返回确认后更新选择，运行时重启后恢复也重用已保存的服务商。
